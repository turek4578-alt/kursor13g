# KURS — рабочий прототип криптообменника

Next.js-приложение с настоящей базой данных (не localStorage, не память
вкладки). Всё, что происходит в одной сессии — регистрация, обмен, KYC,
действия админа — сразу видно всем, кто открыл ту же ссылку, включая
обновление страницы.

Что уже работает: регистрация с кодом подтверждения, вход, обмен с фиксацией
курса на 15 минут, кошельки, история операций, KYC (загрузка фото → авто-
подтверждение), реферальная ссылка, 2FA-переключатель, панель управления
(`/admin`) со сводкой, очередью заявок, пользователями, парами/спредами,
kill switch, audit log.

**Новое: реальная проверка пополнения USDT (TRC20).** Админ может назначить
пользователю конкретный адрес приёма USDT прямо в карточке пользователя
(`/admin/users` → выбрать пользователя → «Адрес приёма USDT»). Как только
адрес назначен, кнопка «Проверить в блокчейне» в кошельке пользователя
реально обращается к публичному API TronGrid и зачисляет только то, что
действительно нашло подтверждение в сети — без придуманных сумм. Платформа
НЕ хранит приватный ключ от этого адреса: ключ должен быть у вас или у
пользователя, чей это кошелёк на самом деле. См. `lib/tron.ts`.

Это **не боевая биржа** — нет реального партнёра по исполнению, нет
блокчейн-мониторинга, нет настоящей кастодии. Все переходы статусов заявки
имитируются по времени (см. `lib/orders.ts`). Полный список того, что нужно
для реального запуска — в `crypto-exchanger-spec.md` (спринты 0–12).

## Вариант 1 — Vercel + Turso (бесплатно, ~10 минут)

Подходит для демонстрации инвестору. Vercel не даёт постоянный диск, поэтому
база данных живёт отдельно, в Turso (тот же SQLite по сути, просто по сети).

### Шаг 1 — создать базу в Turso

1. Зайти на **https://turso.tech** → Sign up (можно через GitHub).
2. В панели нажать **Create Database**, дать любое имя (например `kurs`),
   выбрать регион ближе к вашим клиентам (Frankfurt подойдёт для СНГ/Европы).
3. Открыть созданную базу → вкладка **Connect** → скопировать:
   - **Database URL** — выглядит как `libsql://kurs-xxxxxx.turso.io`
   - Нажать **Create Token** → скопировать токен (показывается один раз)

### Шаг 2 — выложить код на GitHub

1. Зайти на **https://github.com** → New repository → назвать, например
   `kurs-app` → Create.
2. В скачанном архиве с кодом (папка `kurs-app`) выполнить в терминале:
   ```
   git init
   git add .
   git commit -m "initial"
   git branch -M main
   git remote add origin https://github.com/ВАШ-ЛОГИН/kurs-app.git
   git push -u origin main
   ```
   (Git должен быть установлен: `git --version` для проверки. Если его нет —
   поставить с https://git-scm.com)

### Шаг 3 — задеплоить на Vercel

1. Зайти на **https://vercel.com** → Sign up через GitHub.
2. **Add New** → **Project** → выбрать репозиторий `kurs-app` → **Import**.
3. Развернуть **Environment Variables** и добавить четыре переменные:

   | Name | Value |
   |---|---|
   | `TURSO_DATABASE_URL` | значение из Шага 1 |
   | `TURSO_AUTH_TOKEN` | значение из Шага 1 |
   | `SESSION_SECRET` | любая случайная строка, например `a1b2c3d4e5f6...` (30+ символов) |
   | `ADMIN_SEED_PASSWORD` | пароль, который хотите для входа в `/admin` |

4. Нажать **Deploy**. Через 1–2 минуты появится ссылка вида
   `https://kurs-app-xxxx.vercel.app` — она рабочая и постоянная.

### Дальше

- Вход в панель управления: `/login?staff=1`, email `admin@kurs.app`,
  пароль — тот, что указали в `ADMIN_SEED_PASSWORD`.
- Свой домен подключается в Vercel: Project → Settings → Domains.
- Любое изменение кода — `git push` — Vercel передеплоит сам за минуту.

## Вариант 2 — свой VPS (ближе к реальному продукту)

Подходит, если нужен физический контроль над сервером (например, требование
лицензии Кыргызстана про сервер в стране), либо просто без сторонних
сервисов.

### Требования к серверу

Любой VPS с Ubuntu 22.04+, минимум 1 ГБ RAM. Hetzner CX22 (~€4/мес) или
DigitalOcean Basic ($6/мес) достаточно с большим запасом для демо-нагрузки.

### Установка

```bash
# на сервере
sudo apt update && sudo apt install -y nodejs npm nginx git
sudo npm install -g pm2

# залить код (или git clone своего репозитория)
cd /var/www
git clone https://github.com/ВАШ-ЛОГИН/kurs-app.git
cd kurs-app
npm install
```

Создать `.env` файл рядом с кодом:
```
SESSION_SECRET=сгенерировать-случайную-строку
ADMIN_SEED_PASSWORD=ваш-пароль-для-админки
DATA_DIR=/var/www/kurs-app/data
```
(`TURSO_*` не указывать — тогда используется локальный файл SQLite прямо на
диске сервера, ничего дополнительно поднимать не нужно.)

```bash
npm run build
pm2 start npm --name kurs -- start
pm2 save
pm2 startup   # выполнить команду, которую покажет pm2
```

### Nginx + домен + HTTPS

```bash
sudo nano /etc/nginx/sites-available/kurs
```
Вставить:
```nginx
server {
    listen 80;
    server_name ваш-домен.com;
    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```
```bash
sudo ln -s /etc/nginx/sites-available/kurs /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl restart nginx
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d ваш-домен.com
```

Готово — сайт на `https://ваш-домен.com`, база — обычный файл на диске
сервера в `data/kurs.db`, бэкапить можно простым копированием этого файла.

## Локальный запуск (проверить перед деплоем)

```bash
npm install
npm run build
npm start
```
Открыть `http://localhost:3000`. База создастся автоматически в `./data/kurs.db`.

## Структура проекта

- `lib/db.ts` — подключение к базе (async, работает с Turso и с локальным файлом)
- `lib/orders.ts` — машина состояний заявок (`transitionOrder`), единственное
  место, где меняется статус заявки
- `lib/coins.ts` — курсы, генерация адресов, форматирование (серверная часть)
- `lib/auth.ts` — сессии, роли
- `app/api/*` — все эндпоинты
- `app/`, `app/app/*`, `app/admin/*` — страницы (лендинг, кабинет, панель)

Дальнейшая разработка (реальный партнёр по исполнению, реальный KYC-провайдер,
реальная кастодия) описана в `crypto-exchanger-spec.md`, спринты 0–12.
